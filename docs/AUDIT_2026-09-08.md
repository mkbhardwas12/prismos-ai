# PrismOS audit and remediation — 2026-09-08

## Outcome and limits

This pass reviewed the knowledge graph, ingestion/retrieval, chat workflow,
artifact generation, inference transport, recovery, training scripts, dependency
advisories, and public/private file boundaries. It fixed concrete faults and
added regression coverage. It is not a penetration test, a historical secret
audit, a guarantee of correctness, or approval to publish private data.

The application is improved but is **not yet ready to claim secure autonomous
operation, expert factual verification, or complete encrypted disaster recovery**.
Existing worktree changes were preserved. No commit, push, remote backup, private
corpus harvesting, model download, fine-tuning or model promotion was performed.

## Current architecture and capability

| Path | What actually happens | Important boundary |
| --- | --- | --- |
| Ordinary chat | Local retrieval and profile context feed one primary LLM drafting role, surrounded by orchestration and deterministic checks. A separate alternative perspective may run after the answer. | Workflow-role count is not independent expert/model count. Policy approval is not fact verification. |
| PPTX / DOCX request | Bounded local sources and optional attachment context → schema-constrained local outline → completeness validation → local file writer → attachment. | Sources remain untrusted data; output still needs technical and visual review. |
| Knowledge ingestion | Full extracted text → stable source and chunk IDs → real containment/sequence links. | Repeated imports are idempotent. Changed content invalidates stale embeddings. Removed chunks are retired. |
| Graph view | Actual stored relationships, connected/all/isolated scopes, search, source filters, neighborhood inspection and path tracing. | Rendering limits and isolated records are disclosed; decorative lines are not invented. |
| Private inference | Fixed `127.0.0.1:11434`; proxies and redirects disabled for private payloads. | Does not attest the behavior of the local Ollama service or make other integrations offline. |
| Learning scripts | Explicit local experiment, positive-feedback harvesting, training and held-out comparison. | Not autonomous; feedback is not verified truth; data preparation still needs human review. |

PDF and XLSX ingestion exist, but **native PDF and XLSX generation do not yet
exist in the chat artifact lane**. CSV is not an Excel workbook. Public-URL
research is a separate opt-in path, not an automatic vendor-verification step
for every document request. A requested SAP version/landscape does not establish
an executable or supported upgrade path.

## Remediations completed

### Answer quality and observability

- Removed fabricated agent dialogue, unsupported empirical-backing statements,
  self-comparison as validation, and factual-confidence percentages.
- Activity distinguishes deterministic workflow/policy checks from model work;
  synchronous context roles now finish visibly before the long model wait.
- Drafting guidance distinguishes requirements, sources, assumptions and unknowns;
  prohibits invented SAP Notes, compatibility, commands and file-success claims.
- New assistant-derived memory is labeled unverified. Artifact retrieval places
  old conversations/entities in a non-evidence continuity block rather than
  assigning them source citations.
- Failed/empty model responses do not proceed to successful learning. Missing
  Sentinel checks fail closed. Whole mutating chat pipelines are not silently
  retried three times or sent to a hidden fallback model.

### Documents and files

- PPTX/DOCX creation takes precedence over attachment analysis when an attachment
  is provided as source material. Polite creation requests are recognized.
- Local source retrieval now runs before document generation, with bounded
  context and source IDs. Retrieved content is JSON-delimited untrusted data.
- The bridge accepts an optional JSON schema; incomplete token-limited output
  is rejected. A document can attempt one complete replacement, not silently
  repair truncated brackets and claim a partial artifact is complete.
- Validation requires substantive content for the chosen slide layout, not
  merely syntactically valid JSON or speaker notes on a blank slide.
- Generated output uses atomic new-file reservation; generated app directories
  use atomic reservation too. Unit-test artifacts use temporary directories,
  not the user's Downloads.
- File opening is confined to supported generated files. Windows uses no command
  shell. Generated HTML receives a restrictive policy before model-provided
  markup, even if a comment or permissive policy was already present. This is
  not a complete browser sandbox; navigation and host permissions need care.

### Knowledge integrity and recovery

- File-watcher events are consumed instead of discarded. Initial and changed-file
  scans use full-text chunk indexing rather than a 4 KB preview alone.
- Source imports use deterministic identities, atomic writes, source links and
  stable sequence edges. Unchanged content retains evidence freshness; changed
  content invalidates embeddings. Unicode offsets are handled consistently.
- Obsolete owned chunks are excluded from answer retrieval without deleting
  unrelated user records or links. Legacy imports are not silently rewritten.
- Startup no longer re-merges a handoff twice. Existing databases, including
  intentionally empty ones, are authoritative; automatic recovery/demo seeding
  is limited to a database file that was missing before startup.
- A reviewed public knowledge pack and explicit dry-run/apply importer were
  added. Manifest SHA-256 checks bind reviewed text to the imported bytes; all
  documents are validated before writes. No model/network calls are involved.
- A private pre-import SQLite online backup was integrity-checked. Comparing
  the imported database with that snapshot found no loss or content/identity
  changes to existing nodes/edges and no dangling relationships. A repeated
  pack import did not increase counts. Recovery paths/details stay outside Git.

### Privacy, release hygiene and evaluation

- Desktop private inference, vision and embeddings use fixed loopback transport;
  CLI `ask` rejects custom inference URLs. Model-management URLs remain separate.
- Ignore rules cover actual graph/sync/state exports and environment variants.
  A filename-only staged/tracked gate is included in CI; it does not inspect
  secret contents, screenshots or Git history.
- UI/docs now disclose plaintext SQLite, limited graph exports, predictable
  legacy key derivation, actual network features and incomplete sandbox claims.
- Exact evaluation means normalized equality. Empty references, invalid judge
  output, truncated replies, malformed holdouts and invalid margins fail closed.
  The experiment runner requires an explicit evaluation baseline before any
  harvesting/training; no unrelated model tag is silently assumed.
- JavaScript development dependencies were updated; both full and production-only
  npm audits reported zero known vulnerabilities at verification time.
- Six compatible Rust lockfile patch updates (crossbeam-epoch, h2,
  rustls-webpki, tar and two rand versions) reduced the vulnerability-advisory
  count from 32 to 24. No breaking dependency migration was disguised as a patch.

Reimport from the repository root (dry-run is default):

```sh
cargo run --manifest-path src-tauri/Cargo.toml --bin prismos-knowledge -- \
  --app-dir "/absolute/path/to/existing/local/app-data" \
  --pack-dir resources/knowledge/reliable-local-assistant
```

After a verified local backup and review of the dry-run, add `--apply`. Never
point this importer at an unrelated database. If a pack document changes,
review it and update its manifest digest before importing.
The digest detects changed bytes; it is not a publisher signature or independent
verification that the reference content is true.

## Remaining priorities — not silently deferred as complete

| Priority | Finding | Required next work |
| --- | --- | --- |
| P1 | Legacy You-Port key derivation uses predictable identity data; password-based sync lacks an appropriately expensive KDF. Hardware identifiers are not protected encryption keys. | Versioned migration to randomly generated protected keys and a password KDF, preserving legacy recovery; independent review and restore tests before use for remote backups. |
| P1 | Rust dependency advisories include unsupported Wasmtime 27 and document parsers. | Migrate to patched supported versions and verify reachability by shipped platform/feature. Do not treat the current sandbox or untrusted-document parsing as security-cleared. |
| P1 | Cross-device `merge_graph` is not an all-or-nothing identity-validated transaction. | Transactional validation, explicit conflict rules and rollback tests before relying on sync for recovery. Local source imports and snapshot imports have separate, improved paths. |
| P2 | You-Port is a partial graph export, not full application recovery; a state save overwrites one file and keys/settings/source files are not covered. | Atomic versioned snapshots, full recovery manifest, off-device encrypted copy and isolated restore drill. No Git/cloud destination has been configured. |
| P2 | Audit-log instances have independent locks; hashes do not prevent full-file rewriting. Sandbox execution can convert an error to text and still report success. | Shared/file locking, concurrent-append tests and propagation of execution failure. Avoid immutable-log/automatic-rollback claims. |
| P2 | Main-chat retrieval still lacks enforced claim-to-source validation; legacy generated entities and pinned profiles can contaminate context. Context counts/model identity are not fully faithful to the final prompt/routing. | Typed provenance and trust-aware retrieval throughout, exact context/model telemetry, domain evaluation and optional independently grounded review. |
| P2 | File deletion/rename reconciliation and legacy UUID/Python-import freshness/embedding migration are incomplete. | Explicit source lifecycle, backward-compatible migration and dry-run reconciliation. Do not bulk-delete historical data. |
| P2 | PDF/XLSX generation, artifact render QA and genuine bounded research/refinement loops are missing. | Implement format-specific writers/renderers and acceptance checks; budgeted tool/model orchestration with measured quality improvement. |
| P2 | Training data may contain repeated/related questions and unverified positive feedback. | Deduplication, grouped held-out split, independent labels, privacy review and a reproducible evaluation before any training/promotion. |

Before a public release, also inspect staged content and screenshots, scan secret
history, validate Windows/Linux behavior, and resolve CI's existing non-blocking
coverage/lint commands. This pass did not certify those areas.

The remaining 24 Rust vulnerability entries concern `wasmtime 27.0.0`,
`lopdf 0.34.0` and `quick-xml 0.30.0 / 0.31.0 / 0.38.4`. Counts are advisory
matches, not demonstrated exploits. Wasmtime is an active dependency, but the
current application loads its own hard-coded policy module rather than arbitrary
user WASM. Each advisory's actual exposure still needs platform/feature analysis.
Additional unmaintained, unsound and yanked-package warnings remain. Full scan
results are retained in ignored local build logs, not embedded personal data.
